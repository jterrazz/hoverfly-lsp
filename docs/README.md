# hoverfly-lsp — the manual

The manual of this repository: what the language server is, how it is changed,
what proves a change, and how it is released. The vitrine — what the thing does
and how a user installs it — is the `README.md` at the root.

| Chapter                                  | Holds                                                                                                                                                       |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [01-architecture.md](01-architecture.md) | The three layers and the one-way dependency, what each directory of the analysis library owns, what the server adds, how each editor launcher finds the bin |
| [02-developing.md](02-developing.md)     | The toolchain and the gates, which file a change opens, adding a diagnostic, regenerating the reference, where the answers were researched                  |
| [03-testing.md](03-testing.md)           | The suites and what each stands on, the corpus contract, regenerating a golden, and where mechanical proof stops                                            |
| [04-operating.md](04-operating.md)       | What ships to which registry, cutting a release, tokenless npm publishing, the manual half, and the footprint a user carries                                |

Generated pages stand apart in [reference/](reference/): the diagnostic catalog
and the template reference are projections of `packages/analysis`, regenerated by
`npm run docs:diagnostics` and never edited by hand.

The decisions this repository takes are recorded in [decisions/](decisions/),
cut from the `_template.md` beside them. The binding decisions D1–D9 predate
this folder and still live in `research/10-architect-decisions.md`, which
[02-developing.md](02-developing.md) routes to.
