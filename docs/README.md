# The hoverfly-lsp manual

The manual of this repository: what the language server is, how it is changed,
what proves a change, and how it is released. The vitrine (what the thing does
and how a user installs it) is the `README.md` at the root.

| Page                                                  | Holds                                                                                                                                                       |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Architecture](concepts/architecture.md)              | The three layers and the one-way dependency, what each directory of the analysis library owns, what the server adds, how each editor launcher finds the bin |
| [Develop](guides/develop.md)                          | The toolchain and the gates, which file a change opens, adding a diagnostic, regenerating the reference, where the answers were researched                  |
| [Test](guides/test.md)                                | The suites and what each stands on, the corpus contract, regenerating a golden, and where mechanical proof stops                                            |
| [Release](guides/release.md)                          | What ships to which registry, cutting a release, tokenless npm publishing, the manual half, and the footprint a user carries                                |
| [Manual QA](guides/manual-qa.md)                      | The release's manual half: what a human checks in each real editor, and what is already proven without one                                                  |
| [Diagnostics](reference/diagnostics.md)               | Every `HFxxx` code: its severity, trigger, range and message, generated from the analysis package's catalog                                                 |
| [Template reference](reference/template-reference.md) | The Handlebars helpers, faker types and `now` formats Hoverfly templating accepts, generated from the analysis package's registries                         |
| [Decision template](decisions/_template.md)           | The shape a decision this repository takes is recorded in                                                                                                   |

The two reference pages are projections of `packages/analysis`, regenerated by
`npm run docs:diagnostics` and never edited by hand. The binding decisions D1 to D9
predate the decisions folder and still live in `research/10-architect-decisions.md`,
which [Develop](guides/develop.md) routes to, beside the original build plan,
`research/00-master-plan.md`.
